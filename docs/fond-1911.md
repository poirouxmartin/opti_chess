## 3. Compiler drift (measured)

- `C:\tmp\optichess-revue` binary of 17/11 23:05 (linker 14.51, 1 106 944 bytes): S4 unsolved,
  Kd3, value 1751, the exact number of the 17/11 report.
- Clean builds tonight (linker 14.52) of `3bd4bc5`, `385011d`, `e460d9b` and `cb138a3`
  (the 17/11 branch tip itself, 1 001 472 bytes): S4 solved at 9 000, Kf2, value 1829, identical to `main`.
- Both binaries give `bench 2000` signature `29ae53c1996ef1e6`.
- Toolsets installed: `VC\Tools\MSVC\14.44.35207` and `14.52.37025` (dated 2026-11-18 15:42).

So no commit of the review or of `ab-1711` changes the S4 result: the bisection is flat. Long DAG
searches are sensitive to codegen (**hypothesis**: floating-point contraction or ordering in the
WDL / selection arithmetic), and S4 sits on a knife edge. The 26/10 table of
`docs/DAG_EXACT_VERIFICATION.md` (S1 value 1866 vs 1919 tonight, S6 5 000 vs 6 500) was also taken
with an older compiler.

Consequence for measurements: compare binaries built by the same toolset only, and record it.
`bench` now prints `compiler=MSVC <_MSC_FULL_VER>` (e.g. `195237032`).

## 4. Tests

- New `GraphGame.RefreshPropagatesExactValue`: builds a 3-node DAG by hand, checks that
  `refresh_graph_values` writes the graph value (300) into a stale root, keeps the root's own
  uncertainty (current semantics, documented), leaves terminal leaves untouched, and that a child
  whose position is on the game path counts as a draw (root falls back to 100).
- `Endgame.Fine70ExactDagSolvesLadder` **fails in the full harness run on `main` with MSVC 14.52**
  (S4 plays Kd3 within the 20 000 budget) but **passes when run alone**, for both `main` and this
  branch. The test already notes that earlier searches in the same process change its trajectory.
  This is pre-existing (see section 5), not caused by this branch.
