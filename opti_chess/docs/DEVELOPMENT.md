# Building, running and developing OptiChess

## Prerequisites

- Windows 10 or 11, 64-bit
- CMake 3.24 or newer
- Visual Studio 2022 or newer with **Desktop development with C++**
- Git (required by CMake on the first configure to fetch dependencies)

No package manager is required. CMake fetches pinned copies of raylib and robin-map automatically.

## Fast path

From the `opti_chess/` directory, which is where `CMakeLists.txt` and `CMakePresets.json` live:

```powershell
cmake --preset windows-release
cmake --build --preset windows-release
.\build\windows-release\Release\opti_chess.exe
```

For a debug build, replace `release` with `debug` in all three commands. The executable is self-contained with its `resources/` directory in the build output.

## Command-line configuration

If presets are not convenient, this produces the same release build:

```powershell
cmake -S . -B build\manual -G "Visual Studio 17 2022" -A x64
cmake --build build\manual --config Release
.\build\manual\Release\opti_chess.exe
```

Use a generator appropriate for the installed Visual Studio version if needed. The project requires a C++20-capable compiler.

## Visual Studio workflow

1. Open the `opti_chess/` folder, not the legacy `.vcxproj` file.
2. Allow Visual Studio to configure CMake.
3. Select the `windows-debug` or `windows-release` preset.
4. Select `opti_chess.exe` as the startup target, then build and run.

The legacy Visual Studio project references paths on the original author's machine. It remains in the repository for history, but CMake is intentionally the portable build route.

## Runtime behaviour

At startup, OptiChess opens the analysis board and calculates an adaptive memory budget for the search pools from available system memory. The first seconds of startup may therefore be more noticeable on lower-memory machines. The process is designed to cap its search-pool budget, but 8 GB or more system RAM is recommended.

The most useful controls are documented in the [README](../../README.md#controls). `H` also toggles arrow drawing and the on-screen controls panel.

## Validation

The current test harness is interactive:

1. Build the Debug preset.
2. Launch the application.
3. Press `T` to run the configured engine test suite.

For search, move-generation or evaluation edits, also validate representative positions manually in the GUI and check that loading a FEN, starting/stopping analysis and navigating the game tree remain responsive. `ALGORITHMS.md` and `BUGFIXES.md` describe the current engine invariants and prior correctness issues.

Automated CTest coverage is a good next improvement, but it is not claimed by the current project configuration.

## Troubleshooting

### CMake cannot find a C++ compiler

Install the **Desktop development with C++** workload from Visual Studio Installer, then open a new terminal and rerun the preset.

### Dependency download fails during configuration

The first configuration needs network access to GitHub. Check the connection or proxy, then delete only the relevant build directory (for example `build/windows-release`) and configure again. Once fetched, CMake reuses its build tree.

### The application starts but assets are missing

Run the executable generated by CMake from its build output. CMake copies `resources/` beside it after each successful build. If launching a binary manually, place the entire `resources` directory next to the executable.

### A search uses more memory than expected

Close other memory-heavy applications and restart OptiChess; its pool sizing is computed at startup from available RAM. For engine changes, do not replace the pool model with unbounded allocation.

## Project conventions

- Keep runtime assets under `resources/` so CMake can package them with the application.
- Keep third-party libraries out of the repository; add or update pinned CMake dependencies instead.
- Avoid adding allocations to search and evaluation hot paths.
- Keep Windows-specific system integration isolated in `windows_tests.*` where possible.
